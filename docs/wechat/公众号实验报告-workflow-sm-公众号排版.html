管住 AGENT · 实验记录 2026.10

一次把 Agent 的流程
“管住”的实验

workflow-sm：把下一步从 Agent 的记忆里拿出来，交给独立状态机校验。

不是替 Agent 做事，而是让“做到哪一步”有一个可核对的事实。

本文是一次本机技术实验记录，不是第三方认证、法律审计意见，也不代表产品已经覆盖所有 Agent、所有桌面端或全部合规要求。

很多人以为，给 Agent 一份足够详细的提示词，它就会照着做完。实际使用里，更常见的是：它跳过中间核验、重复提交已经完成的步骤；窗口一关，做到哪里也说不清；出了问题以后，只能翻聊天记录猜它到底做过什么。

我想验证一件小而具体的事：能不能把“下一步该做什么”，从 Agent 的记忆和自觉里拿出来，交给一个独立的状态机来约束？

01

TEST

这次实验要验证什么

先划边界，再讲结果

workflow-sm 是什么？

一个通过 MCP 接入的有状态工作流引擎。它不替 Agent 调研、写作或改代码；它只保存流程状态，并只把当前允许执行的那一步交给 Agent。

  1. Agent 不能越过当前步骤直接“交后面的作业”；
  2. 流程中断后，进度和已经产出的内容仍能保留；
  3. 人能从看板实时看到工作流状态；
  4. MCP、重试、跳转与并行前置步骤能稳定工作。

没有验证的内容也要先说清：这不是 Claude、Codex、ZCode 的横向测评；不是自动化 Runner 实验；更不是一份可以用于司法或法律审计的完整证据链。

02

LOAD

实验环境与载荷

一个四步线性流程

实验使用项目内置的 research-to-report 流程：调研、分析、起草、保存。状态机对外暴露 5 个 MCP 工具，Agent 仍然是具体任务的执行者。

顺序步骤任务
01research产出 3 条关键事实
02analyze提炼 2 条核心洞察
03draft起草 100 字内段落
04save确认并保存最终产物

图 1｜实验用四步 YAML 流程定义。顺序写进状态机，而不是让模型“记住”。

03

CHAOS

故意让 Agent 乱来

不只验证“能走通”，还验证“能拒绝”

我们故意尝试四类错误：跳到第二步、报告不存在的步骤、重复报告已经完成的步骤，以及跳过中间步骤直接报告第三步。它们都被拒绝；只有按正确顺序报告，流程才会完成。

workflow-sm 不判断 Agent 写得好不好，但会阻止它把流程事实说乱。

图 2｜本轮测试：147 passed，0 failed。通过数对应已编码场景，不等同于全部业务风险已被覆盖。

实验 A｜跳步会发生什么？

先让 Agent 在 a 还未完成时直接报告 b，再让它在完成 a 后跳过 b 直接报告 c。两次都被状态机拒绝。

图 3｜跳步测试实际输出节选：直接报告后续步骤、重复报告、乱序报告都被拒绝。

WEB

把流程状态放到看板上

列表、进行中、倒带、完成：均为原始浏览器截图

一条真实演示流程完成第 1 步后停在 analyze：看板显示 1/4（25%），保留已完成输出，明确标出当前活跃步骤。随后又分别截取了列表、倒带后与完成态。

图 4｜运行列表：一条 1/4（25%）的流程出现在看板中。

图 5｜倒带前：research 已完成，analyze 是当前活跃步骤。

实验 B｜回滚不是重开

在详情页把目标步骤选为 research，执行 rewind。系统将 research 重新激活，并把它之后的步骤还原为待执行；不是另开一条流程，也不是假装已完成的输出还有效。

图 6｜倒带后：流程回到 research，后续步骤被重置。

图 7｜完成态：四步流程全部完成，步骤状态与输出仍可回看。

05

RESULT

汇总结果，以及还没做到的事

结论要和边界放在一起

本轮验证：147 passed · 0 failed

覆盖：核心状态机、持久化、混沌 Agent、MCP 协议、重试/跳转、并行前置步骤、看板与 SSE。

不代表：所有真实业务风险已消失，更不代表已形成法律意义上的完整审计证据。

当前边界

它不评价产出质量；不会自动把所有桌面端 Agent 变成受控执行器；也没有覆盖身份、授权、完整输入输出、外部操作的法律级证据链。不同 MCP 客户端能否稳定执行整套协议，仍需要逐个实测。
