# 路线 B 证伪实验 — 驱动指南

> server 已注册为 `workflow-sm`。开一个**新的** Claude Code 窗口(让 MCP 工具被发现),
> 把下面的 prompt 贴进去跑。

---

## 方式 B:状态机驱动(实验对象)

把这段贴进新开的 Claude Code 窗口:

```
请用 workflow-sm 这个 MCP server 跑一个工作流。步骤:

1. 先读 `examples/sample-workflow.yaml` 的内容
2. 调用 start_workflow 工具,把 YAML 内容作为 yaml 参数传入,主题用"远程工作的利弊"
3. 然后 STRICTLY 按返回的指令推进:执行每一步 → 调用 report_step_result 报告结果 → 拿下一步 → 重复直到完成
4. 每一步的 output 要是该步骤实际做出来的内容(不要敷衍)
5. 全程不要跳步,不要一次性做两步

完成后告诉我:你总共调用了几次工具,顺序是什么。
```

### 观察 B —— 重点关注(agent 老不老实):
- [ ] agent 是否**每次只报一步**、严格 `start→report→report→report→report`?
- [ ] 还是它"嫌烦",想一口气把几步合做,或跳过 report 直接给最终答案?
- [ ] 中途如果把 step_id 报错(守卫拦截),它能否自我纠正?
- [ ] 最终工具调用次数 = 1(start) + 4(report) = 5 次?

---

## 方式 A:菜谱自执行(对照组)

同样主题,但不走状态机,纯靠 prompt 让 agent 自己看着 YAML 干:

```
请按下面这份 YAML 工作流执行任务,主题是"远程工作的利弊":

(把 `examples/sample-workflow.yaml` 的内容贴在这里)

你按 steps 的顺序自己执行完这 4 步,每步之间不需要问我。
最后把每一步的产出列出来。
```

### 观察 A —— 重点关注(菜谱够不够用):
- [ ] agent 能自己把 4 步串起来做完吗?(通常能,这是它的强项)
- [ ] 但:如果做到一半被打断,能"从第 3 步恢复"吗?——试着在它做到 draft 时打断,再让它继续
- [ ] 产出是**可审查、可 diff** 的吗?(A 的执行过程是个黑盒,只有最终文本)
- [ ] 同样的 prompt 跑两次,过程**一致**吗?(确定性)

---

## 关键对照(赌注 1)

| 维度 | 方式 A(菜谱) | 方式 B(状态机) | 差距明显吗? |
|---|---|---|---|
| **断点恢复** | 打断后能否从中间继续? | `get_run_status` + `report` 能精确恢复 | |
| **执行可审查** | 只有最终文本 | 每步状态/输出/时间戳都可查 | |
| **过程可 diff** | 无 | callLog + steps 记录完整 | |
| **确定性** | agent 可能每次编排不同 | 顺序由 server 强制锁定 | |
| **agent 配合度** | n/a(它自己说了算) | 是否老实按协议走?← 核心观察 | |

**填完这张表,三个赌注的答案就出来了。**

## 协议层已验证(我已完成的)

- 引擎逻辑:15/15(推进、跳步守卫、断点恢复)
- MCP 协议全链路:10/10(initialize/list/call,裸 JSON-RPC 直连)
- 可移植性:server 不绑任何特定客户端,任何 MCP 客户端都能连
